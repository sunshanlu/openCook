在新隔离状态目录和已确认的两个访问账号下选择少量新视频。运行前核实访问额度、每日运行窗口、原有未决请求和账号归属；不复用生产状态目录冒险迁移。

确认分类及提取各阶段、请求唯一归属、原文留存和数据库幂等结果。抽样对照视频，记录漏食材、漏步骤、错误数量、结构合法性和请求次数。2026-10-18 已完成一条样本，分类／提取各一次请求，用户明确接受验收成功并取消新增语义拒绝规则；直接视频对照未完成。详情见[验收报告](../research/xhs-spec18-live-sample-20261018.md)。

## 受控切换（待独立授权）

1. 暂停旧执行器，核实 worker 停止且没有第二个执行者。
2. 保存任务配置、请求／会话记录、SQLite（使用一致备份方式）与节流状态；记录提交版本。
3. 核对旧未决请求，由旧路径收尾或人工裁决。新引擎不自动迁移这些请求。
4. 核实小样本及故障验收证据后，为新任务显式选择 v2。
5. 检查分类入队、提取完成、阻塞范围、心跳和请求次数；异常时先保存现场并停止推进。

## 恢复

保留原数据和未决请求身份。已创建的 v2 任务继续由 v2 恢复，不能直接交给旧引擎重发；停止接收新任务后核对未决请求，再决定恢复旧执行路径。数据库增加的任务表是附加数据，不删除它来“回滚”。
