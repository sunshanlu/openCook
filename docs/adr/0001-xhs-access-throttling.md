# 小红书访问节流按窗口额度与退避冻结,而非累计发送上限

分类账号在 2 小时内只发了约 143 次点点请求,仍在打开笔记页时撞上 300013,说明触发风控的是页面访问量和连续活跃时长,不是发送次数。因此节流改为:访问额度、发送额度、每日活跃时段三类窗口约束,各访问账号独立计数;限流冻结后按连续次数翻倍退避(2 小时起,上限 24 小时)。取代原先"累计 500 次发送后停下等人工"的试验上限。

## Considered Options

- 保留累计发送上限并调小:不会约束页面访问和活跃时长,无法避免 300013,且硬停让托管流水线卡在人工环节。
- 冻结后固定时长恢复:反复撞墙会让平台对该账号越来越严,指数退避更安全。

## Consequences

发送额度通常比访问额度宽松,这是有意的:每条笔记至少一次页面访问,风控压力主要来自访问。新策略前 3 天按半额爬坡。
