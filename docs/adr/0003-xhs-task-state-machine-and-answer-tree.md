# 小红书导入由持久化任务状态机推进，等待回答使用行为树

2026-10-18 决定将一个视频的一次分类或提取作为独立导入任务，由新的任务执行器唯一控制阶段转移，在等待回答阶段使用行为树选择观察和恢复动作。优先采用 transitions 与 py_trees，具体版本及同步／异步接入方式须先通过适配验证；项目继续负责请求身份、提交核对、SQLite 持久化、预算与重启恢复。

这一划分将阶段合法性与现场行动选择分开，避免现有请求控制逻辑与新执行器同时推进任务。第一版保留双账号调度和队列，迁移单任务控制逻辑及必要的协调器接口。相比在现有条件分支外再包一层状态机，这需要迁移旧控制权，但能使重试与恢复只有一个决策入口。

远端点点提交无法与本地数据库组成原子事务，因此先保存发送意图，提交结果不明时核对原请求。任何预算耗尽都不能把未决请求当作已结束：原请求已可靠收尾才进入待人工复核，否则阻塞并保留恢复位置。这会使部分原先直接进入审核的页面恢复耗尽路径停止推进，换取避免重复提交、错误归属和遗失迟到回答。

框架负责内存执行语义，不承担业务持久化；重启从本地事实和远端核对重建执行，不序列化框架实例。固定树结构，开放有限参数。第一版先验证新任务，不自动迁移历史未决请求，也不让两个执行器接管同一任务。

完整阶段、行为树、预算、验收和切换约束见[设计方案](../design/xhs-task-state-machine-and-answer-tree.md)。现有[访问节流决策](0001-xhs-access-throttling.md)和[会话保留决策](0002-xhs-import-session-retention.md)继续适用。
