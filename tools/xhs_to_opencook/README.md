# 小红书点点 → openCook

## 长期托管运行

```bash
xhs-to-opencook supervise pipeline --profiles bloggers.txt --output output/profiles-live --skip-collect
xhs-to-opencook status
xhs-to-opencook pause
xhs-to-opencook resume
xhs-to-opencook stop
```

`supervise` 可托管 `run/pipeline/collect/classify/extract/export` 的原参数，所有控制命令
支持 `--state-dir`。一次性命令仍可独立运行。`--skip-collect` 仅用于已有博主清单的
pipeline 续跑，不重采主页。macOS 当前 GUI 登录会话使用状态目录中的 launchd 配置，
不安装开机自启。登出或重启后用 `resume` 手动恢复；已完成任务须显式启动新任务。

监督状态保存在 `--state-dir/supervision/`：`job.json` 是任务和重启记录，`worker.json`
是心跳及操作截止时间，`items.json` 是累计预算和失败窗口，`control.json` 是控制意图，
`outbox.json` 是飞书待发队列。每10秒心跳；60秒失联或操作超时才恢复。每15分钟最多
重启3次，耗尽或代码/存储/状态错误等待人工。`pause/stop` 立即禁止新提交，最多30秒
保存原请求；恢复先核对历史，不保证服务器生成已停止。

托管模式把网络和平台故障作为全局等待，间隔5/15/30/60分钟后每小时检查。
登录/验证码保留专用Chrome，每5分钟检查，处理好自动继续。连续3条同类失败或
最近10条有5条失败，先等30分钟再试探，后续每小时一次；3轮仍失败等待人工。
试探先检查页面和引用，再放行一条有额度的视频，不重置次数。每视频每阶段最多
2次尝试，累计主动处理35分钟；平台等待、暂停和电脑休眠不计入。等待截止时间、
尝试和预算跨重启保留。

发送状态不明核对最多60秒，仍不明确则保存现场、隔离会话、转人工，继续其他视频，
不直接重发。`unknown` 也转人工，不计明确分类成功数。无法保存或隔离则等待人工。
已审核冻结项普通恢复不重试，仍使用 `--retry-review` 显式开启补处理。任务自动结束
与缺口全部解决分开报告；主页采集缺口和人工项都列入部分完成。

飞书使用本机 `lark-cli` 的 bot 身份，只向 `whoami --as user` 中配置的本人发送。
每30分钟汇报；登录、持续故障、阶段及全量结束另发一次。只发送摘要，不发送原始
回答或凭证。失败按1/5/15/60分钟重试，稳定幂等键1小时内去重；超出窗口的关键事件
允许少量重复提醒。全量结束后只保留通知补发，送达后退出，`stop` 可立即结束补发。
日志20MB×5份轮转，失败现场保留于本机。通知失败不影响采集。

以下历史一次性运行说明中“无法关联即停批”的规则，在托管模式下由上述隔离和
全局等待策略替代；严格引用、次数和人工审核冻结规则仍适用。

个人本机使用的 Python 命令行工具。把用户挑选的小红书**视频笔记链接**交给网页版点点，自动读取菜谱 JSON，生成可导入 openCook 的文件。第一版支持 macOS、Python ≥3.12 和 Google Chrome。

支持指定博主主页批量采集；不遍历搜索结果，不在评论区发消息，不调用其他模型 API。通过格式检查的菜谱自动导出；检查只验证结构和目标引用，**不代表已核实视频内容或估算用量**。

## 安装

先安装 Google Chrome 和 Python ≥3.12。macOS 自带的旧 Python 不适用。可通过 Homebrew 安装 Python：

```bash
brew install python@3.14
cd /Users/agiuser/Projects/openCook/tools/xhs_to_opencook
/opt/homebrew/bin/python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

工具直接使用已安装的 Chrome，无需运行 `playwright install`。其他位置的仓库或 Python 请调整路径。也可用 `python -m pip install .` 安装非 editable 版本。

## 登录与运行

```bash
xhs-to-opencook login
```

在弹出的专用 Chrome 中手动登录，然后回到终端按 Enter。工具确认登录后关闭窗口，保存登录状态。后续运行会重新打开同一配置目录。

创建 UTF-8 的 `videos.txt`，每行一个完整链接。支持 `www.xiaohongshu.com/explore/...`、`/discovery/item/...`、个人主页内单条笔记路径，以及 `xhslink.com` 短链接。尽量保留分享链接中的 `xsec_token`；过期令牌可能使原本存在的视频无法访问。空行忽略，UTF-8 BOM 可接受；不要混入分享文案。

```bash
xhs-to-opencook run --links videos.txt --output ./output
xhs-to-opencook run --links videos.txt --output ./output --refresh
```

运行期间保持专用 Chrome 打开，可以切到其他应用。日常提交不再主动将 Chrome 拉到前台，
同一会话串行处理最多 5 条不同视频，再在原标签页建立新会话。首次启动浏览器或重建已关闭
的标签页仍可能显示窗口。登录失效或验证码出现时，终端提示暂停：在 Chrome 中手动处理，
回到终端按 Enter 后继续。Ctrl-C 可停止，重新运行同一命令可续跑。

默认复用成功缓存，中断任务核对后续跑。每个视频、每个阶段默认最多 2 次提交，失败后换新会话再试，仍失败则转人工审核并继续下一条。JSON 格式修正计入总次数，整个阶段最多修正一次。`--max-attempts` 可调整上限；已有待审核记录仍须人工审核后显式解除。页面适配失效时停止整批，保留已完成结果。

| 选项 | 默认值 | 用途 |
| --- | --- | --- |
| `--interval` | `2` 秒 | 两次 AI 提交之间的最小间隔 |
| `--chat-batch-size` | `5` | 一个会话最多提交的不同视频数 |
| `--max-attempts` | `2` | 每视频、每阶段总提交上限，含格式修正 |
| `--retry-review` | 关闭 | 人工审核后，重新尝试当前输入范围的待审核任务 |
| `--timeout` | `180` 秒 | 单次点点回答等待时长 |
| `--state-dir` | `~/Library/Application Support/openCook XHS` | 专用 Chrome、缓存和原始回答目录；login/run 应使用相同目录 |
| `--non-interactive` | 关闭 | 登录/验证码需要处理时立即停止，适合自动任务 |
| `--refresh` | 关闭 | 忽略菜谱成功缓存，重新提问 |

间隔与超时须为大于 0 的有限数。状态目录与输出目录不能互相包含。同一状态目录同时只允许运行一个任务。

## 博主批量流程

`bloggers.txt` 使用 UTF-8，每行一个完整博主主页链接（`/user/profile/<博主ID>`），
保留分享链接的令牌参数，空行和 BOM 忽略，重复博主按 ID 去重。

```bash
xhs-to-opencook pipeline --profiles bloggers.txt --output ./output
xhs-to-opencook collect --profiles bloggers.txt --output ./output
xhs-to-opencook classify --profiles bloggers.txt --output ./output
xhs-to-opencook extract --profiles bloggers.txt --output ./output
xhs-to-opencook export --profiles bloggers.txt --output ./output
```

`pipeline` 串联整批采集、整批分类、提取和打包。其他命令只执行指定阶段；
`classify/extract/export` 要求指定博主已有持久采集记录，不隐式采集。
所有命令共用 `--state-dir`、运行锁和登录配置。`export` 无需浏览器，可在意外退出后离线打包。

若跳转到小红书 `/website-login/error` 安全限制页（如“访问频繁，请稍后再试”、300013），
记录 `platform_restricted` 并停止整批，交互模式也不会自动重试。限制解除前不要续跑；
该情况不作为单条坏链接或人工审核失败。已提交的未决请求保留，恢复后先核对原回答。

每次采集重新滚动全部可访问历史笔记，不因遇到旧笔记停止；按笔记 ID 去重。
页面自身分页响应的明确 `has_more=false` 才表示已到末页。
连续三轮无新增但没有可信末页信号时标记不完整；保留已采集记录、继续其他博主。
本次未再出现的历史笔记仍保留。图文跳过，无法识别类型的笔记标记 `type_unknown`，
保留在采集结果中等待复核，不打开详情页。
网页可访问内容不包含已删除或隐藏内容；采集完整性在报告独立列出。

采集 URL 时同时保存标题、作者、作者 ID 和封面 URL；从主页分页响应和可见卡片
读取，空字段不覆盖已有缓存。原始分页记录保存到采集目录的 `profile-pages/`。
分类和提取直接使用采集 URL 和缓存元数据，不再打开笔记详情页。
提取复用分类来源；未决请求恢复仍使用原请求来源。旧缓存字段缺失时明确标记
“标题未记录”或“作者未记录”，缺封面仍可导出文字；可重新采集作者主页补全字段。

分类时点点必须返回目标 ID、`tutorial/non_tutorial/unknown` 及理由。
有制作过程、食材和步骤的内容算教程，包括饮品、烘焙、酱料、腌菜及多道菜；
用量不全仍进入提取。纯成品展示、吃播、探店、商品推荐、食材知识跳过；
无法读取或依据不足为 `unknown`，下次重试。分类和提取都核验引用和明确完成状态，
各默认最多 2 次提交、一次格式修正，每次 AI 提交遵守 `--interval`；修正也计入总次数。

确认的教程和非教程永久复用分类；普通失败和 unknown 下次自动重试。
达到 `--max-attempts` 的视频保存 URL 和错误码到 `manual_review.csv`，等待人工审核；
普通续跑、刷新、重分类或提高上限都不会自动重试这些视频。审核后通过 `--retry-review` 开启新的尝试轮次。
`pipeline/classify --reclassify` 重问分类；`pipeline/extract --refresh` 重做菜谱提取。
两项独立，不会因为重新提取而自动重问非教程。
整批分类之后，教程在新对话里提取，提交时重新核验点点引用的笔记 ID。
旧版成功菜谱补做一次分类，通过后复用原 JSON、名称和封面。
重分类为非教程/未知/失败时从本次汇总排除，历史菜谱缓存保留用于回查。
提取刷新失败也不删除历史成功结果，报告单独记录最新提取失败。

累计 ZIP 只包含指定博主 ID 所属、当前确认教程且有成功菜谱的记录，
跨博主按笔记 ID 去重，不混入其他历史作者。不同作者同显示名称仍按 ID 区分。
逐条保存 JSON、状态和原始回答；`extract/pipeline/export` 结束时生成 ZIP，
可控中断也打包已有成功结果，`collect/classify` 正常结束只更新清单和 JSON。
已有 ZIP 在采集/分类期间可能对应上次打包，需执行 `export` 获取当前最终 ZIP。

新增输出：`collection.json`（博主状态、累计笔记及归属）、`video_links.txt`（视频候选）、
`tutorial_links.txt`（当前教程，包括提取失败的链接）。报告列出分类理由、待分类/提取数量、
无法判断、类型未知、采集不完整与各阶段状态。`raw/` 中分类和提取分别存入
`<笔记ID>/<尝试时间>/<classify或extract>/`，不混淆修正问答。
数据库新增独立表，保留原菜谱和 URL 映射；原 `run --links` 继续按输入文件导出，
不要求教程分类，仍每条更新 ZIP。默认输出、bloggers.txt 和状态文件已忽略；
自定义路径请放在仓库外或加入忽略规则。

新错误 `profile_invalid` 表示主页链接无效；`collection_required` 表示需先采集。
退出码沿用 0/1/2/130；采集不完整、未知或单条失败为 2，页面适配/登录阻塞为 1。
真实站点验收见 [验收记录](VALIDATION.md)，模拟页面不能证明实站分类准确性。

## 输出与导入

输出目录每完成一条任务都会更新，文件包含**本次输入列表的成功结果**，不会把历史所有缓存混入当前文件。

| 文件 | 内容 |
| --- | --- |
| `recipes.zip` | `recipes.json` 和 `images/<note-id>.jpg`，优先用此文件导入 |
| `recipes.json` | 独立导入文件，封面使用远程网址；网址可能过期 |
| `report.json` | 成功/缓存/失败/跳过、尝试次数、错误码、估算用量、封面失败、未处理数量、待审核数量 |
| `manual_review.csv` | 中文列名、UTF-8 BOM；URL、标题、作者、失败阶段/次数、错误码、原始记录路径及人工填写列 |
| `manual_review_links.txt` | 当前待审核视频的去重 URL，方便逐条打开 |
| `raw/<note-id>/<timestamp>-<attempt>/` | 来源、引用证据、原始/修正回答、转换结果或错误，异常时含页面截图及 HTML |

在 Android openCook 的文件导入入口选择 `recipes.zip`。菜谱集名称使用作者；食材用途保留在名称里，例如“白糖（杀水用）”和“白糖（料汁用）”。原视频链接、原始用量、估算说明及注意事项在备注中。

导入名称为 `菜名（作者·视频末8位ID）`，同视频多道菜加序号。极少数名称冲突时追加完整笔记 ID，并将实际名称写回缓存。工具不设置 `identifier`：openCook 按名称跳过已存在菜谱。重复导入同一文件应跳过；`--refresh` 后若点点改变菜名，可能成为新菜谱，不覆盖此前用户编辑。

仅来源明确时保留份数和标准 PT 时间。“一夜”“至熟”等保留为文字。点点应保留明确用量，估算缺失/模糊用量，按 `estimated` 标记写入备注与报告；格式校验无法判断模型标记是否符合视频事实。封面使用已登录浏览器获取，验证图片内容后转换为 JPEG。封面失败不影响文字导出，ZIP 不放无效图片。

## 状态和恢复

状态目录中 `chrome/` 存登录状态，`cache.sqlite3` 存逐条状态及短链接映射，`covers/` 存本地封面，`raw/` 存历次原始回答。输出也会复制相关笔记的原始记录。浏览器配置、缓存、依赖和默认输出均已加入 Git 忽略规则；自定义输出请放在 Git 仓库外或自行加入忽略规则。这些目录可能含登录信息、带令牌链接、个人页面及回答，应仅保存在本机。

常见错误：

| 错误码 | 处理 |
| --- | --- |
| `link_invalid` / `not_video` | 检查是否为可访问的视频笔记；更新完整分享链接 |
| `reference_mismatch` | 回答中的视频 ID 或请求 ID 不匹配时，换会话重试一次；仍不匹配则转人工审核并继续下一条。发送前引用不符也使用此码，不发送错误引用 |
| `answer_timeout` / `answer_incomplete` | 未看到页面明确完成信号，或显示中断；可提高超时后重试 |
| `generation_busy` | 发送前上一轮仍忙碌，当前请求未发送；封存并换会话，两次尝试仍失败则转人工审核 |
| `manual_review_required` | 当前视频当前阶段达到尝试上限，写入 CSV 并继续下一条；人工审核后用 `--retry-review` 补处理 |
| `json_syntax_invalid` | JSON 格式或语法错误，包括围栏不完整、重复键或非标准数字；保留原文，尝试修正 |
| `json_schema_invalid` | JSON 已解析，但缺字段、字段类型/值或时间格式不符合要求；保留原文，尝试修正 |
| `image_failed` / `image_missing` | 文字仍可导入；检查报告，必要时刷新获取新封面 |
| `page_unsupported` | 页面版本变化，停止整批；需修正浏览器适配后再继续 |
| `login_required` | 重新 login 或取消 `--non-interactive` 手动处理 |
| `state_busy` | 同一配置已有进程，等待完成或停止已有任务 |

若关闭了 Chrome，工具会在后续尝试重新打开专用配置；任务失败仍保留已导出的菜谱。不要删除状态目录来解决单条失败；普通失败可续跑，待人工审核任务保持跳过。登录彻底失效时可先备份 `raw/`、`covers/` 和数据库，再移走 `chrome/` 并重新 login。

退出码：`0` 全部成功/缓存/跳过，`2` 部分任务失败，`1` 输入、运行环境或页面适配阻塞，`130` 用户中断。报告中的 `verification=format_and_reference_only` 说明验证范围。

### 点点会话批次

`run`、`classify`、`extract` 和 `pipeline` 支持 `--chat-batch-size`（正整数，默认 5）。
同一会话串行处理最多 5 个不同的已提交视频，第 6 个视频创建新会话。
缓存命中、重复及发送前不可访问不占容量；非教程与发送后的失败占一个位置。
失败后的重试或 JSON 修正都换新会话；同一视频在每个会话只占一个位置。
分类与提取分别管理会话，pipeline 完成分类后才进入提取。
旧大容量批次恢复时使用持久容量与新配置中的较小值；已经满 5 条则封存。
已准备但未提交的请求迁移到新批次，保留请求 ID 和尝试次数；已提交请求先核对原历史。

每次提交重新核验输入区唯一视频引用，提示词和内部回答包含 `note_id`、唯一
`request_id`。当前回答按页面实际轮次关联；历史恢复另核对页面正常加载的服务器消息
ID、原问题和回答。内部包装校验后剥离，openCook 导入 JSON 字段不变。
分类和提取均默认使用短提示词（分类版本3、提取版本2），不发送冗长JSON Schema。
提取只提供一份含来源包装的完整JSON示例，保留原始用量、估算、分阶段食材、多菜品及
时间要求；严格校验保持不变。新请求及重试使用当前版本，已提交请求恢复时保留原文本。

请求在按 Enter 前持久保存。续跑优先处理未决请求；无法确认原会话或历史请求时
停止提交，不会直接重发或建立额外会话。普通等待默认 180 秒，提交间隔默认 2 秒。
先等待真实输入框可见、可编辑且刷新完成（最多 60 秒），再等待 0.5 秒；
写完内容后再等待 0.5 秒，确认发送控件就绪后发送。
专用 Chrome 使用实际窗口的内容尺寸；输入框和发送按钮必须完整处于网页可见区域，
且输入框未被加载层遮挡，才允许填写，避免固定虚拟视口把底部输入区排到窗口外。
若匹配的当前回答明确显示“（暂无内容）”，且完成标记及空闲状态持续5秒，记录空回答
证据并跳过10分钟冷却，封存旧会话，换新会话再试一次。
仍未结束的生成或其他无回复情况冷却 10 分钟并继续观察；迟到有效回答直接保存。
冷却结束先核对唯一请求，记录观察证据，封存旧会话，再在空白新会话核验引用并重试。
旧请求以 `superseded_by` / `previous_request_id` 关联新旧请求；不把旧会话的迟到回答用于新请求。
默认第二次仍失败便持久保存 `manual_review` 状态，输出 CSV 并继续下一视频。
冷却截止时间与未决尝试次数跨重启保留。旧成功结果不会因新上限变为待审核。
发送前发现上一轮未结束时记录 `generation_busy`，封存并换新会话继续同视频。
此类发送前失败也占一次尝试额度，避免连续新建会话；不计入已提交视频容量。
未发送请求的换会话意图跨重启保留，不要求该请求在历史中存在。
发送前忙碌时，旧会话封存与请求的重试/人工审核状态在同一数据库事务中保存；
事务内写入失败则一起回滚。原始记录在事务提交后更新，恢复以数据库状态为准。
恢复已缓存的回答时，若生成结束状态不符，按原冷却期限继续观察；期限尚未建立时
从恢复检查起冷却10分钟。确认空闲后复用原回答，仍无法确认则核验身份、封存并换会话；
尝试上限已到则转人工审核。旧未决请求超过本轮上限也直接封存并转人工，保留原次数。
若页面自身历史接口明确成功返回空消息列表，且没有轮次节点，以 `history_unavailable`
保存证据；仅已有会话、轮次、发送时间及原问题的持久请求允许封存后换会话恢复。
可单独执行 `export` 从缓存打包。

### 人工审核与补处理

`manual_review.csv` 使用 UTF-8 BOM，Excel 等工具可直接显示中文。
每行共 12 列：笔记 ID、阶段、标题、作者、URL、状态、失败次数、错误码、请求 ID、
原始记录路径，以及可填写的“人工审核结论”“补全备注”。逗号、引号和换行使用标准 CSV 转义。
每次导出按请求 ID 保留人工填写内容；解除审核后保留原行并标记“已解除待审核”。
旧 CSV 重导出时删除“失败原因”列，保留人工填写内容；详细异常保存在原始记录中。
`manual_review_links.txt` 只列当前待审核的去重 URL。清单范围与当前输入一致。

编辑 CSV 的结论或备注不会自动提交。人工核对 URL 和原始回答后，用 `--retry-review`
明确开启新一轮补处理（仍最多 2 次提交）。建议将已审核的 URL 放入单独的输入文件，缩小处理范围：

```bash
xhs-to-opencook run --links reviewed-videos.txt --output ./review-output --retry-review
xhs-to-opencook classify --profiles reviewed-bloggers.txt --output ./output --retry-review
xhs-to-opencook extract --profiles reviewed-bloggers.txt --output ./output --retry-review
```

`run` 执行菜谱提取，分类待审核使用 `classify`。命令必须使用原 `--state-dir`。
如果保留了历史成功菜谱，补处理时还需 `--refresh` 才会重新提取。
人工备注作为审核记录保留，不会直接成为菜谱内容；补全结果仍经过来源和格式校验。

当前账号的旧版页面未实测到可用停止按钮；旧会话无法确认结束时通过封存并换会话恢复。
新会话须确认空白、输入可编辑、引用唯一才发送。回答 JSON 中的视频 ID 或请求 ID
不匹配使用 `reference_mismatch`：拒绝该回答，在两次总尝试额度内换会话重试一次；
仍不匹配则转人工审核并继续下一条，CSV 的错误码保留 `reference_mismatch`。
报告中的流程状态错误码为 `manual_review_required`，用于表示已转人工，CSV保留实际失败码。
页面实际会话/消息绑定无法核验、页面适配失效、登录失效或浏览器意外关闭
仍保留未决请求并停止，以供恢复。
`report.json` 的 `chat_batches`、`pending_requests` 和 `raw/.../request.json`
记录容量、来源、请求关联与恢复原因。格式与标识校验通过仍需抽查视频内容准确性。

### 单视频恢复与批量继续

分类和提取的外层只遍历视频、保存结果，不再重新调用内层进行第二轮重试。
内层统一管理打开浏览器、恢复历史、换会话、发送、等待与回答校验。
导航超时、页面执行环境因导航销毁、连接异常或浏览器关闭属于可恢复页面故障：
先尝试3次，各次间隔5秒；仍失败则原地等待5分钟，再尝试3次。
页面恢复不增加点点请求尝试次数；点点请求仍按 `--max-attempts`（默认2次）计数。
恢复次数及等待截止时间保存在状态目录 `recovery/`，重新启动继续原期限和次数。
已发送或发送状态不明的请求先核对原会话，不直接重发。
登录失效、验证码或平台限制不会自动解决，按同一有限恢复策略等待人工处理；
恢复耗尽后保存原请求、会话及 `page_recovery_exhausted` 原因，封存会话并转人工审核，
普通续跑保持跳过该视频，再处理下一条。
未知浏览器错误、代码异常或请求/视频/会话状态矛盾保存现场并停止本轮。
外层在视频结束后检查没有未决请求才继续，不能把尚未恢复的请求当作普通失败跳过。

### 并行分类与提取

```bash
xhs-to-opencook pipeline --profiles bloggers.txt --output ./output --execution parallel --skip-collect
xhs-to-opencook supervise pipeline --profiles bloggers.txt --output ./output --execution parallel --skip-collect
```

默认仍为 `--execution serial`。并行模式由一个协调器管理分类、提取两个工作进程，
共用专用 Chrome 登录配置，各有一个独立顶层窗口与点点会话。两边分别遵守
`--interval`，同时各最多一个未决请求。已有教程先入持久队列，新确认教程追加队尾；
队列暂空时提取等待，分类结束且队列排空后才结束自动处理。

每阶段有独立心跳、预算、失败窗口与日志；工作进程退出只断开自己的浏览器连接。
网络、账号、平台问题及连续失败触发两边共同等待；Chrome整体崩溃统一重建并核对
两个原请求。局部工作进程问题独立恢复，需要人工时另一边可继续处理。
`status` 显示 `workers`、`workers_alive` 与队列各状态；控制命令作用于整个任务。

公共输出只由协调器发布。首份可用菜谱立即打包，此后每新增20条成功笔记、暂停、
停止及结束时更新累计 ZIP；多菜品笔记按一条成功笔记计。ZIP原子替换，导出失败重试
不会重新请求菜谱。浏览器连接信息位于 `supervision/browser.json`，CDP仅监听本机回环。

并行模式不自动降级。首次切换须先验证实站两个会话同时生成不互相打断；生产迁移
应暂停、核对未决请求并备份数据库与监督状态，保持原请求、次数和审核冻结。
